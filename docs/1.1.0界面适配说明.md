# 1.1.0 界面与适配

## 小米14截图反馈对应修改

| 反馈 | 修改 |
| --- | --- |
| 开关与概念图不一致 | 使用自绘CompoundButton，固定凹槽、渐变拨头和阴影，避免HyperOS/其他系统替换样式 |
| 三个按钮分散、过于靠底 | 单一凹槽导航座；系统安全区之外另留20dp间距 |
| 选中页面不明确 | 当前页使用绿色实体按键、白字；其他入口透明；保留selected及无障碍描述 |
| 拟物程度和过渡不足 | 累计/秒表改为凹入仪表区，列表/操作区使用浮雕边缘，统一拨钮与按键动效 |

设计借鉴锤子时钟的材质层次、边缘高光和实体操作感，未使用或复制其专有素材。

## 适配策略

- 按逻辑dp和实际WindowInsets布局，不按特定机型屏幕像素写死位置。
- API30以上使用systemBars/displayCutout/mandatorySystemGestures；API26—29使用对应兼容读取方式。
- 小屏及大字体允许内容滚动，主导航始终保留；不是强制压缩按钮尺寸。
- 宽且低的横屏将信息区和操作区左右排列；平板主内容最大720dp。
- 字体遵循系统缩放；大字体时累计和秒表上下排列，避免相互挤压。
- 动画使用系统属性动画，不循环播放，关闭系统动画时直接切换状态。

## 验证边界

自动化布局检查不能替代HyperOS、ColorOS、OriginOS、One UI、原生Android等真实设备测试。系统权限弹窗、微信分享和厂商隐藏手势条行为仍需目标手机复核。具体自动测试执行结果见《构建验证》。

## GitHub与更新安装

用户提供仓库 `NothingBigger1/ShikeCounterSource`，并明确允许以公开仓库上传源码。代码中不包含个人计数数据、数据库、签名密钥或本机SDK路径。

本地APK沿用1.0.0的Debug签名，versionCode从1增至2，可在签名一致的情况下覆盖升级并保留数据库。GitHub Actions每个运行器生成的Debug签名可能不同，其产物不能保证覆盖本地APK；需要稳定分发时应配置长期Release签名。

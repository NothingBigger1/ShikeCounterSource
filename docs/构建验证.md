# 构建验证

交付版本：1.1.0（versionCode 2），包名 `cn.shike.counter`。

## 已执行

- Android Gradle Plugin 8.1.2、Gradle 8.2、JDK 17、Android SDK 34 构建 `assembleDebug` 成功。
- Android `lintDebug` 成功；最终报告无问题。
- `apksigner verify --verbose` 验证 APK 签名有效（v2）。
- `aapt dump badging` 确认应用名称“拾客”、最低API26、目标API34、主Activity及定位权限。
- 使用生产 `ExcelExporter` 生成测试工作簿，覆盖通用/已购买/未购买、无定位、有定位、XML特殊字符、秒表格式。
- 使用 Python ZIP/XML 检查及独立 `openpyxl` 读取，验证两个工作表、3条明细、1条汇总、坐标空值与有值、人数汇总及地址转义。工作簿不包含公式节点。
- 源码使用 Google Java Format 整理。
- 新版 Android `lintDebug` 报告为 `No issues found`。
- Robolectric自动化测试6项通过，0失败、0错误：在API26/29/34上各验证安全区和自绘开关；覆盖320×640、360×800、393×873、412×915、480×1000、800×1280、800×400逻辑dp的导航/开关布局，另验证1.5倍字体及分类计数→暂停流程。

## 未执行

本机没有已连接的安卓设备，也没有可用模拟器。已执行的Robolectric测试属于模拟Android框架的自动化测试；尚未执行真机安装、真实触摸与动画观感、数据库进程恢复、GPS和地理编码、系统主题切换、微信实际接收等实机验收。它们仍需按《验收清单》在目标手机验证，不将自动测试称为主流厂商真机全覆盖。

APK 使用本地生成的 Debug 签名，适合首版安装试用，未配置用于商店发布的长期 Release 签名。签名文件在工程目录之外本地保留，不纳入源码包或GitHub。

## 构建环境说明

当前环境网络与系统目录受限，构建时将已有SDK与依赖缓存复制到任务 `work` 目录，并使用临时本地 Maven 仓库。此配置不写入公开工程；项目本身使用官方 Google/Maven Central 仓库与 Gradle Wrapper，普通开发机按 README 即可构建。
